# 高光局部材质匹配与合成

最终图始终以原图为底，使用 `scripts/composite_natural_highlights.py`；依赖 Pillow、numpy。不得直接以整面生成图替换源像素。

## 输入与对齐

- `source`：原图，不覆盖。
- `highlight_mask`：原尺寸0/255二值蒙版，依据原图明确圈定反光及必要的极小接缝空间。
- `protect_mask`：可选的同尺寸二值蒙版，覆盖贴纸、真实结构或应保留的磨损，优先于高光范围。
- `candidate`：已查看的AI补片候选，有效高光非空时必需。
- `texture_reference_boxes`：原图中已查看的干净材质框 `[left, top, right, bottom]`，右/下边界不包含。每边至少16像素，不含高光、保护区、半透明轮廓、天线、孔洞、按键或结构边。不能只以“不在高光mask内”判断供体干净。

同尺寸且已对齐的候选按原坐标使用；其他候选只裁切/缩放候选到源坐标，局部裁图必须记录真实源位置。主体长宽比偏差不超过6%；不能提高阈值掩盖漂移。查看后设置 `confirm_alignment=True` 与 `confirm_texture_references=True`，这两项是执行者的检查记录，无须重复询问用户。

原不透明高光核心默认要求候选alpha≥192。候选抗锯齿处的RGB经目视核实有效、且仅由源图alpha控制最终轮廓时，可显式降低 `candidate_alpha_threshold` 并记录值和原因；不得因此接受完全透明缺口，也不能篡改候选alpha来绕过检查。

CLI中 `--texture-references` 指向JSON框数组文件，另传 `--confirm-alignment`、`--confirm-texture-references` 和独立的 `--report`。具体选项以脚本帮助为准。

## 合成方法

1. 有效范围 = 高光mask ∩ 原图alpha>0 ∩ 非保护区。只写此范围的RGB，整幅alpha逐点保留；alpha=0隐藏RGB和范围外RGBA不变。
2. 沿灯条短轴从原图紧邻同材质两侧建立低频明暗，保留真实轮廓变化，滤掉会被拉伸成条纹的行/列细纹。不能把过曝内部的原白色混回成品。
3. 将二维细纹与低频明暗分开。对于原图的细密周期网纹，以干净参考的方向和频率为依据，在目标附近匹配位置、幅度与尺度；AI候选只提供受限的可用细节。不能把候选云斑、横带或者供体结构当作纹理。
4. 内部接缝匹配不扩展蒙版。确认反光覆盖半透明边缘时允许修复其中RGB，保留其原alpha，使透明轮廓的位置、透明度和尺寸不变。候选在原不透明核心应有可靠覆盖；边缘可沿原材质续接，不能用生成alpha替换源alpha。
5. 无有效高光的PNG逐字节复制原文件，不生图、不重编码。

此方法针对具有足够同材质参考的局部反光。参考区有结构、原图纹理不适合周期匹配或两侧并非同一材质时，不套用当前样本的框和参数；先检查并针对该面调整。过曝下的内容属于材质推断，不宣称真实隐藏细节已恢复。

## 校验与视觉验收

从保存后的PNG重新读取并核对：尺寸相同、整幅alpha相同、高光外RGBA零差异、保护区零差异、alpha=0隐藏RGB零差异，变化像素全部在允许范围内；源文件哈希不变。无高光面应文件哈希相同。

逐处查看原尺寸和约3倍放大：补片的明暗、纹理方向、尺度和密度应连贯，不应出现矩形雾块、横竖条纹、假天线、亮圈或明显硬接缝。数值与像素保留检查不能替代视觉验收；仅“比上一版好”不等于通过。

蒙版返修只能依据原图中实际漏选的反光，并保存旧版、新版和依据。不得为了通过校验而把候选误改的正常区域算入高光。

旧 `composite_highlights.py` 的 boundary/feather 和 `finalize_restore.py` 保留作历史兼容，不作为当前仅去高光自然材质匹配的默认输出流程。
